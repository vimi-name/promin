Initialize promin in the open project root.

Principle: humans define meaning; agents clarify and implement.

Do not start with a questionnaire. Detect the Git root, project mode, languages,
manifests, lockfiles, build/test stack, conventions, backlog/references,
available tools, OS, and existing promin state. Before the plan, perform only a
bounded metadata preflight; do not run a hidden full repository scan.

Build one concise resolved plan with the goal, mode, workspace units, detected
stack, profile composition, standards/sources, autonomy, language, material
rights, planned scans/external actions, first operations, and material unknowns.

Use Morok Tower Studio and safe reversible defaults when evidence is
insufficient. Ask only about material ambiguity that affects authority,
architecture, or an irreversible result and has no safe default.

Show the plan. In `ask` and `safe-auto`, wait for confirmation or natural-language
clarification. In `unsafe-auto`, record the plan and continue inside current
authority. After init report status, profile revision, next action, whether a
human decision is needed, and the `promin doctor`, `promin refresh`, and
`promin audit` commands.
