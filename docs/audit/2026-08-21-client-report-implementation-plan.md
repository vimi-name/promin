# Client Report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a short client-facing PDF only from a verified, claim-safe Promin client report JSON without making the PDF an authority or product-acceptance artifact.

**Architecture:** Core emits a canonical client report JSON in the public-workflow slice. A separate tools-only renderer validates that JSON, binds its digest in the output metadata, renders a concise static PDF, and never imports Core state mutation paths. Rendering occurs after terminal evidence collection, not as a substitute for it.

**Tech Stack:** Python 3.13, canonical JSON, ReportLab if already available or an explicitly installed local rendering dependency, Poppler rendering for visual verification.

**Spec:** `docs/audit/2026-08-21-public-workflow-and-tooling-design.md`

## Global Constraints

- The PDF is a client presentation artifact, not a release decision, runtime proof, or authority source.
- Input JSON must be strict canonical and all claims must be false unless separately supported by terminal evidence explicitly included in the report.
- Renderer output is create-only; it must refuse an existing destination and bind the input SHA-256.
- No source or D: evidence root is changed by rendering or visual verification.
- Do not generate a client PDF before final evidence collection; fixtures prove renderer behavior only.

```python
def load_client_report(path: Path) -> dict[str, object]:
    value = load_json_strict(path, root=path.parent)
    if value.get("schema") != "promin.client-report.v1":
        raise ClientReportToolError("client report schema is invalid")
    if any(item is not False for item in value["claims"].values()):
        raise ClientReportToolError("client report carries promoted claims")
    return value
```
